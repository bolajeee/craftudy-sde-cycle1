## CraftStudy build — week 6 (~75 min, 20:00–21:15)

Did: wrote the auth suite (signup, login, identical 401 for unknown email vs wrong password, legacy user with no password hash) and the tasks suite (auth middleware, CRUD happy paths and failures, invalid ids, and user isolation: Bob gets 404 on Alice's task and it stays unchanged). Added `tests/helpers/auth.js` to insert a user and sign a JWT directly, so task tests never hit the login rate limiter. Committed the failing tests before the fixes. 42/42 passing, lint clean. Removed week 1–3 leftover files and rewrote the README so setup ends at green tests.

Broke: the new tests found two real bugs. `GET /tasks` had no comma between the query and its params, so `'SELECT…'[req.user.id]` indexed the string and Postgres received the query `E` (500 on every list call). `PATCH` checked `req.body` for an empty update, but Zod strips unknown keys, so `{ priority: 'high' }` got past the guard and produced `SET  WHERE` (500). Fixing them, I added `next(error)` in a `catch` without adding `next` to the handler signature, and the `ReferenceError` hid the real error. Then I typed `result.body` instead of `result.data`. Lint caught the first, only the tests caught the second. I also committed a "fix" before running the tests and had to amend it.

Learned: edit, lint, test, then commit. After validating, make every decision on the validated data, never the raw body. A broken error handler hides the error it exists to report. The login limiter counts every attempt, including 400s, so tests that log in repeatedly will start getting 429s.
