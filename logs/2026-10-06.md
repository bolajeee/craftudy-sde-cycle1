# 2026-10-06 — Week 3

* **Minutes:** ~1 hour 30 minutes
* **Focus:** Express migration, JSON middleware, and request validation

### What I worked on

* Installed and introduced **Express** into the existing Tasks API.
* Migrated `GET /tasks` from the raw Node `http` server to an Express route.
* Added `express.json()` middleware to parse incoming JSON request bodies.
* Migrated `POST /tasks` to Express while keeping the existing `tasks.json` persistence.
* Tested the API with `curl` and confirmed valid task creation returns `201 Created`.
* Tested invalid input and confirmed that the API initially accepted incorrect data, which exposed the need for proper validation.
* Installed **Zod** for request validation.
* Created `src/validation.js` with a task schema:

```js
const createTaskSchema = z.object({
  title: z.string().min(1),
  completed: z.boolean()
});
```

* Used `safeParse()` to validate `request.body` before creating a task.
* Tested validation failures:

  * Missing `title` → `400 Bad Request`
  * `completed` as a string instead of a boolean → `400 Bad Request`
* Confirmed valid input still creates a task successfully.

### Key concept learned

I learned the difference between **middleware** and **validation logic**. The validation currently works inside the route, but it is not yet separated into reusable middleware.

The next step is to move this validation into a `validateTask` middleware so that the route itself can focus on creating the task.
